# Design decision log

This file records every decision about fiscalclock's visual identity and design system: the question, the options considered, the choice, and the reason. Newest entries go at the bottom of each table. The wiki page "Design decision log" mirrors this file; when they differ, this file wins.

"Owner" means the maintainer chose. "Basis" means a technical call made on evidence, which the maintainer can reopen like any other.

## Phase 1: interview (1 Nov 2026)

| ID | Question | Options considered | Choice | Why |
| --- | --- | --- | --- | --- |
| DD-001 | Relationship to the sibling project workclock | Same system with a different symbol; loose cousins; independent; umbrella brand | **Independent.** Nothing is copied from workclock: no colours, typefaces, logo ideas, tokens, page names or site stack. | Owner: "This project is independent of workclock." |
| DD-002 | Primary audience | Rust developers; Python data users; JS/TS developers; finance and analytics teams; AI agents and their users | **All of them, with no single primary group**: developers in all three languages, finance and analytics teams, and AI agents. | Owner. The identity has to read as credible to an accountant and as precise to an engineer. |
| DD-003 | How often non-programmers read the docs | Often; sometimes, through a developer; rarely | **Rarely.** Docs are written for people who write code; plain-English explanations support them but do not lead. | Owner. |
| DD-004 | Reference brands | Owner named the sites they admire | **Admired:** Stripe Docs, Claude Docs, Linear, Vercel, Resend. **Not a reference:** workclock. | Owner. All five admired sites are restrained, high-contrast and treat dark mode as a full theme; the research checks what they have in common. |
| DD-005 | Dark mode | Equal to light; light first; not needed | **First-class, equal to light.** Every colour pairing and every asset is designed and checked in both themes. | Owner. |
| DD-006 | Personality | Five 1–5 sliders: serious–friendly, technical–approachable, minimal–rich, classic–modern, quiet–distinctive | **2.5 on every slider**: balanced, leaning very slightly towards serious, technical, minimal, classic and quiet. | Owner. The half-point lean is read as "calm and precise, but not cold"; Phase 3 states this reading so the owner can correct it. |
| DD-007 | What the logo should be about | Periods and tiling; the 53rd week; ledger and grid; a clock reference; wordmark only; no preference | **No preference: show options.** | Owner. Phase 3 presents distinct concepts. |
| DD-008 | Vector logo files, given that the Canva plan has no SVG export (checked 1 Nov 2026: export formats offered were PDF, JPG, PNG, PPTX, GIF and MP4) and no Brand Kit | Upgrade Canva; author SVG elsewhere | **Author logo and icon SVGs in an open-source SVG editor (Inkscape) and keep them in the repo as the masters.** Canva is used for raster cards. | Owner: "install any opensource svg editor and work in that." |
| DD-009 | Website and docs stack | Decide now; decide later | **Not decided. Assume nothing.** Tokens are kept framework-neutral (W3C format plus plain CSS custom properties). Superseded by DD-030 on 2 Nov 2026. | Owner: "do not assume anything yet." |
| DD-010 | Font licences | Open licences only; any | **Open licences only (SIL Open Font License).** | Owner. |
| DD-011 | Wiki page names and structure | Follow workclock; independent | **Independent.** | Owner. |
| DD-012 | Extra assets beyond the brief (slides, social banners) | Owner unsure | **Open.** Phase 3 recommends what, if anything, to add. | Owner: "I'm not sure." |

## Phase 4: design system (1 Nov 2026)

| ID | Question | Options considered | Choice | Why |
| --- | --- | --- | --- | --- |
| DD-015 | Light-theme text colour | Keep the Phase 3 value `#191918`; use `#1a1a19` | `#1a1a19`, the same value as the dark theme's subtle background | One value fewer in the palette; 17.11:1 on the light background, so nothing is lost. Basis. |
| DD-016 | Token format and build | Style Dictionary 5.7.1; Terrazzo 2.10.0; a standard-library Python generator | **Standard-library generator** ([`scripts/build_tokens.py`](scripts/build_tokens.py)) reading strict DTCG 2025.10 files and a resolver document | No dependencies, same habits as the repository's other check scripts, and Style Dictionary does not yet read resolver documents. The files stay strict so Terrazzo can read them as a cross-check ([research](research/design-tokens.md#72-write-our-own-or-use-style-dictionary-or-terrazzo)). Basis. |
| DD-017 | CSS variable prefix | None; `--fc-` | `--fc-` | Prevents collisions with framework variables such as Tailwind's `--color-*`. Basis. |
| DD-018 | Dark-mode switching | `light-dark()`; selector blocks | **Selector blocks**: system preference by default, `data-theme` on `<html>` overrides | Works for every token type, not only colours, and maps onto every docs framework surveyed. Basis. |
| DD-019 | Shadows | A shadow scale; none | **None.** Raised surfaces use `color.bg.raised` and a border. | Fewer tokens, and borders read the same in both themes; a shadow on near-black is nearly invisible. Basis. |
| DD-020 | Number style | Default figures; tabular figures in tables only; tabular figures wherever numbers are compared | **Tabular lining figures wherever numbers or dates are read in columns or compared**: tables, results, diagram labels, code-adjacent figures | Dates are the product's output; equal-width digits keep them aligned. IBM Plex Sans figures are tabular by default; the CSS rule also covers fallback fonts ([research](research/typography.md)). Basis. |
| DD-021 | Logo geometry | Phase 3 sketch as drawn; refined drawing | **Refined.** The bracket is straight lines on a 64-unit grid with an 8-unit stroke. The parenthesis is the band between two half-ellipses, cut flat at the bracket's height, so its stroke tapers from about 8.3 to 6.9 units like a typeset parenthesis. A separate 16-unit drawing with 2 px strokes serves 16 to 23 px. | Exact geometry can be rebuilt and checked; the small drawing keeps the symbol legible at favicon size ([`scripts/build_brand_assets.py`](scripts/build_brand_assets.py)). Basis. |
| DD-022 | Lockup proportions | Symbol as tall as the ascenders; taller | **Bracket height 0.82 em**, overhanging the ascenders and the baseline by 0.04 em each; gap 0.28 em; wordmark in IBM Plex Sans SemiBold with -10 units of tracking per letter. | A first version at 0.93 em made the bracket stroke (0.143 em) clearly heavier than the letters' stems (about 0.108 em); at 0.82 em it is 0.126 em, a little heavier, which gives the symbol presence without dominating. Basis, checked by eye on rendered exports. |
| DD-023 | How the brand files are made | Draw in Canva; draw by hand in Inkscape; generate from geometry and font outlines, render with Inkscape | **Generate** every SVG from the geometry and IBM Plex Sans outlines with a script, and **render every PNG with Inkscape**. Canva holds an editable social-card template built on the generated background. | Reproducible and exact: the colours are read from the token build, so assets cannot drift from the tokens. The Canva plan cannot export SVG (DD-008), and Canva's editing tools cannot set a typeface, so Canva text cannot match the wordmark. Basis. |
| DD-024 | Icon background where the surrounding colour is unknown (app icons, `favicon.ico`, docs.rs) | Transparent; light tile; dark tile | **Dark tile** (`color.bg.subtle` of the dark theme) with the dark-theme logo colours. The SVG favicon stays transparent and switches colours with `prefers-color-scheme`. | A tile reads on light and dark surfaces alike; docs.rs gives custom logos no help in its dark themes ([research](research/asset-specs.md)). Basis. |
| DD-025 | README banner content | Lockup, description and a small year strip; lockup and description only | **Lockup and description only.** | Without labels, the small strip was decoration rather than information. Basis. |
| DD-026 | Smallest lockup | 96 px wide; as small as the symbol's master drawing allows | **The lockup is at least 24 px tall (about 170 px wide) on screen and 30 mm wide in print.** Below that, use the symbol alone, with its small drawing from 16 to 23 px. | The lockup always uses the master drawing, which DD-021 reserves for 24 px and up; a 96 px lockup would shrink it to about 14 px. Basis; found in review. |
| DD-027 | How links are told apart from body text | Colour only; colour and underline | **Underline every link in running text**, in the accent colour. | The accent against body text is 2.75:1 (light) and 1.72:1 (dark), below the 3:1 that WCAG technique [G183](https://www.w3.org/WAI/WCAG22/Techniques/general/G183) needs for colour alone, so colour cannot be the only cue (1.4.1). Basis. |
| DD-028 | Date style in prose | ISO everywhere; ISO in data, day-month-year in prose | **ISO `YYYY-MM-DD` in code, tables, results and diagrams; "1 Nov 2026" in running prose**, as the README and wiki already write it. | Keeps data unambiguous and machine-readable, and matches the project's existing prose. Basis. |
| DD-029 | Illustration | Decorative illustrations or stock imagery; none | **No decorative illustration.** The library's own diagrams, drawn to scale from verified dates, and real output are the imagery. | Finance experts judged sites mostly by rejecting flashy graphics, and decoration that does not inform reads as templated ([research](research/trust-and-credibility.md)). Basis. |

## Phase 5: website (2 Nov 2026)

Versions and terms below were checked on 2 Nov 2026.

| ID | Question | Options considered | Choice | Why |
| --- | --- | --- | --- | --- |
| DD-030 | Website framework | Astro Starlight 0.42.8; Docusaurus 3.10.2; VitePress 1.6.4; Next.js with Fumadocs (excluded by DD-001); plain Astro; Rspress 2.0.23; Material for MkDocs or Zensical; mdBook | **Astro Starlight, pinned to an exact version.** | Owner, on research. Starlight has local search ([Pagefind](https://pagefind.app/docs/)) and language tabs that keep the reader's choice "across page navigations" ([Tabs](https://starlight.astro.build/components/tabs/)) built in, and loads JavaScript only for interactive components ([islands](https://docs.astro.build/en/concepts/islands/)). Its theme script sets `data-theme` on `<html>` before the first paint and its styles sit in a cascade layer, so `tokens.css` themes it without overrides (read in the 0.42.8 package source). It is before 1.0 and has no built-in versioning, so the version is pinned and versioned docs wait until 1.0. |
| DD-031 | Hosting | Vercel Hobby; Vercel Pro; GitHub Pages; Cloudflare Pages | **Vercel Hobby**, a project in the maintainer's personal Vercel account, served at `fiscalclock.karthik.nz` through a CNAME record at Cloudflare set to DNS only. | Owner. Hobby is "restricted to non-commercial personal use only" ([fair use](https://vercel.com/docs/limits/fair-use-guidelines)); the site is unpaid, ad-free and takes no donations. Hobby cannot connect repositories owned by a GitHub organisation, and `Karthik-beta/fiscalclock` belongs to a user account. |
| DD-032 | Which build of the library the site runs | Build the Rust core to WebAssembly during the site build; install the published npm package | **The published `fiscalclock` npm package, pinned to an exact version.** | Vercel's [build image](https://vercel.com/docs/builds/build-image) lists no Rust toolchain. The site then shows what users install, not unreleased work on `main`. The WebAssembly file is 121 KB compressed (measured on the 0.1.0 build). Basis. |
| DD-033 | First-release scope | Landing page, spec, API reference and changelog only; plus a playground; plus files for AI agents; plus new guides; plus Vercel Web Analytics | **Landing page, guides (getting started in each language and a guide to the definition format), spec, API reference, changelog, a playground, and files for AI agents** (`llms.txt`, `llms-full.txt`, a Markdown copy of every page and a "copy page as Markdown" button). **No analytics.** | Owner. |
| DD-034 | Language tab a first-time visitor sees | Python; JavaScript; Rust | **Python.** The reader's choice is then remembered across pages. | Owner. Python is the language most finance and analytics readers use. |
| DD-035 | API reference | Three generated references (rustdoc, a Python generator, TypeDoc); one reference written from `spec/api-v1.md` with a tab per language | **One reference with Rust, Python and JavaScript tabs**, linking to docs.rs for Rust detail. | The bindings return the core's JSON unchanged and differ mainly in naming (`bindings/python/README.md`, `bindings/js/README.md`), so three generated references would repeat each other in three designs. docs.rs does not accept custom themes ([docs.rs](https://docs.rs/about)). Basis. |
| DD-036 | Playground state and errors | Keep state on the page only; keep the definition in the URL | **The definition lives in the URL fragment**, so a playground state can be shared as a link. Dates are always entered, never read from the clock. Errors shown are fiscalclock's own error objects with their JSON path and hint. | Design rules 6 and 7 in `AGENTS.md`. No JSON Schema for definitions exists yet, so the library's own validation is the only complete check. Basis. |

## Phase 6: website redesign (3 Nov 2026)

The owner judged the first build of the site "over old" and asked for a modern design for the website only. The logo, icons, banners and cards stay as they are. The goal set by the owner is trust, credibility, usefulness and reach with developers and their AI agents. Versions below were checked on 3 Nov 2026.

| ID | Question | Options considered | Choice | Why |
| --- | --- | --- | --- | --- |
| DD-037 | How modern the website looks | Keep DD-006's 2.5 on classic–modern; move the website only towards modern | **About 4 of 5 towards modern, for the website only.** DD-006 still applies to the brand files. DD-019 (no shadows) and DD-029 (no decorative illustration) still apply. | Owner, after seeing the first build. The first build read as old because of a heavy 700-weight heading, one flat surface for header, sidebar and content, stock Starlight chrome, a small year strip below the fold and no evidence above the fold. |
| DD-038 | What the landing page's first screen is | A. Live engine: a working date lookup beside the headline; B. The year, drawn: a full-width strip that draws itself once; C. Datasheet: code beside its output with large counts | **A. Live engine.** A visitor enters a date, picks an example definition, and the published npm package's WebAssembly answers in the page. The answer's week is marked on the year strip. | Owner. It shows usefulness in the first seconds, and every value on screen is real output, not illustration (DD-029). It reuses the playground's code. |
| DD-039 | Website typeface | Keep IBM Plex Sans, set with lighter headings and tighter spacing; a newer open-licence sans with IBM Plex Mono kept for code | **[Mona Sans](https://github.com/github/mona-sans) (SIL Open Font License 1.1, `@fontsource-variable/mona-sans` 5.3.0) for text and headings; IBM Plex Mono stays for code and data.** The lockup, banners and cards keep their IBM Plex outlines (DD-013, DD-023). | Owner chose from a specimen of IBM Plex Sans, Mona Sans, Geist and Hanken Grotesk in both themes beside the real lockup. Geist is Vercel's typeface and risked reading as a template; Hanken Grotesk is close to Plex in feel. All four have equal-width digits (measured), which DD-020 needs. Instrument Sans was not considered (DD-001). |
| DD-040 | Theme on the landing page | Follow the system; dark-first landing | **Follow the system**, as DD-005 says. Both themes get the same design effort. | Owner. |
| DD-041 | How evidence is shown on the landing page | Large counts with small labels; short sentences with the number inline and a link to the check | **Short sentences with the number inline, each linked to the file or workflow that proves it.** | Large counts with small labels are the default treatment on generated pages and say nothing about how a number was reached. A linked sentence lets a developer or an agent check the claim (evidence rule 1). |
| DD-042 | Surfaces and corners | One flat surface; layered surfaces with borders | **Two surface levels**: the page, and raised panels (the live lookup, code blocks) on `color.bg.raised` with a border. **Corners by role**: 12 px for panels, 8 px for buttons and inputs, full for chips. | Layering gives hierarchy without shadows (DD-019). One radius on everything reads as a template kit; radius by role tells the reader what kind of thing each element is. |
| DD-043 | Layout below the landing page's hero | One prose column 720 px wide, as on docs pages; full-width sections | **Full-width sections.** Each section opens with a large heading and a lead paragraph. The explanation sits beside the real code or output it describes, the year strip runs across a band of the subtle surface, and short points sit in a grid. A closing call to action names the next step. | Owner, on 3 Nov 2026: the first redesign was "not looking modern enough". Full-page screenshots showed the cause: below the hero, the page used about half of a 1280 px screen for some 3,000 px, as a stack of code, bullet lists and a table. The band and the grid use surfaces and spacing, not shadows or decoration (DD-019, DD-029). |
| DD-044 | Site navigation | Starlight's header (search, GitHub, theme) and no site footer; header links to the main sections and a footer on every page | **Header links to Docs, Playground, API and Changelog, and a footer with the version, the licence and the main links.** On narrow screens the header links move into Starlight's menu. | A visitor on the landing page had no way to the docs except the hero's buttons, and every page ended without one. Both are Starlight component overrides, so a Starlight upgrade keeps them. |
