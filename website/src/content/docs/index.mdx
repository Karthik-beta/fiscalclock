## Why you can check the results

- **Shared conformance vectors.** The vector files in [`conformance/`](https://github.com/Karthik-beta/fiscalclock/tree/main/conformance) are run by the test suite of every package. Expected results come from cited sources or from generators written independently of the library, never from the library's own output.
- **External oracles.** Week-based years are checked against Python's ISO 8601 week dates (`date.isocalendar()`) for every year from 1600 to 2399, and the NRF 4-5-4 definition against the 53-week years [NRF publishes](https://nrf.com/resources/4-5-4-calendar) (2006, 2012, 2017 and 2023).
- **A second implementation.** A deliberately slow day-by-day reference implementation is compared with the core for every date from 1900 to 2200 across 960 generated definitions.
- **Property tests.** Periods tile their year without gaps or overlaps, nest correctly, and round-trip through `shift` and through `format` and `parse`. Week-based years have 364 or 371 days and 71 long years in every 400.
- **Identical output in every language.** On every push, [CI](https://github.com/Karthik-beta/fiscalclock/blob/main/.github/workflows/ci.yml) runs all vectors through Rust and through the Python and npm packages on Linux, macOS and Windows, and requires the raw outputs to match the Rust output byte for byte.
- **Reproducible verification.** Every date-arithmetic claim in the design documents is reproduced by a standard-library script in [`research/verification/`](https://github.com/Karthik-beta/fiscalclock/tree/main/research/verification), which CI reruns on every pull request.

These statements are taken from the [project README](https://github.com/Karthik-beta/fiscalclock#why-you-can-check-the-results), where each one links to its check.

## Packages

All three packages are built from the same Rust core and return the same JSON for the same input. Version 0.1.0 is the first release; the definition format and API are version 1 drafts and may change before 1.0.

| Package | Install | Supports |
| --- | --- | --- |
| [Python package](https://pypi.org/project/fiscalclock/) | `pip install fiscalclock` | CPython 3.10 and later, and free-threaded 3.14; wheels for Linux, macOS and Windows |
| [npm package](https://www.npmjs.com/package/fiscalclock) | `npm install fiscalclock` | Node.js 22 and later, and browsers (WebAssembly) |
| [Rust crate](https://crates.io/crates/fiscalclock) | `cargo add fiscalclock` | Rust 1.85 and later, `no_std` with `alloc` |
