This page lists the operations of API version 1 and how each language names them. The normative contract, with every argument rule and error path, is the [API spec](/reference/spec/api-v1/); the Rust crate's full API is on [docs.rs](https://docs.rs/fiscalclock/0.1.0/fiscalclock/).

Every operation is defined once, in the Rust core. The Python and npm packages convert their native values to the core's JSON API and back, so they return the same results as the crate.

Each example uses the definition `retail-4-5-4.json` from [the quick start](/start-here/quick-start/), except `format`, which needs two naming schemes and uses `two-schemes.json` from [Labels](/guides/labels/#ambiguous-labels). Each prints exactly the output shown under it.

All operations except `validate` are methods of a calendar, and take their arguments in the same order in every language, as the examples below show. Optional arguments are keyword arguments with a default of `None` in Python, optional parameters in JavaScript, and `Option` values in Rust, where `period` takes `Option<u32>` and `format` takes `Option<&str>`. In Rust, periods are passed as `&Period`, levels as `Level` and dates as `Date`.

In Python and JavaScript, a definition is JSON text or the equivalent dict or object. A `level` is one of `"year"`, `"quarter"`, `"period"` and `"week"`; in Rust it is a `Level`. A `period` argument is a period returned by another operation, or just its coordinates `level`, `year` and `index`: the core recomputes the period from them ([API spec](/reference/spec/api-v1/#operations)). Dates follow [Dates and intervals](/guides/dates-and-intervals/#calendar-dates-only).

## Values

A **period** has `level`, `year` (the fiscal year number under the default scheme), `index` (1-based within the year, and empty for a year), `start`, `end_exclusive`, `last_day`, `days`, `weeks` (empty unless the year is week-based) and `has_extra_week`. In Python it is a frozen dataclass with `datetime.date` fields, in JavaScript a plain object with ISO date strings, and in Rust a `Period` struct whose `last_day()` is a method ([API spec](/reference/spec/api-v1/#period)).

A **location** has the `date`, the `year`, `quarter`, `period` and `week` periods that contain it, and its 1-based `day_of_year`, `day_of_quarter`, `day_of_period` and `day_of_week` ([API spec](/reference/spec/api-v1/#location)).

## Errors

A failed operation raises `FiscalclockError` in Python (a subclass of `ValueError`), throws `FiscalclockError` in JavaScript, and returns an `Err` in Rust. Every error has a stable `code`, the JSON `path` of the offending field or argument, a `message` and, where one helps, a `hint`. Some codes carry `details`, such as the candidates of an ambiguous label. In Python and JavaScript, the error's attributes describe the first error and `errors` holds them all; in Rust, building a calendar returns every error as `Errors`, and the other operations return one `Error`.

The codes, and the operations that raise each one, are listed in the [error catalogue](/reference/spec/api-v1/#error-catalogue).

## The JSON API

Each package also exposes the core's JSON API, which takes and returns JSON text exactly as the core produces it. For the same definition and arguments, the three return the same bytes ([API spec](/reference/spec/api-v1/)). The `definition` and `args` arguments are JSON text, and `op` is an operation's name, such as `locate`. In Rust, `validate` and `call` are in the `fiscalclock::json` module.

| What | Python | JavaScript | Rust |
| --- | --- | --- | --- |
| Validate a definition | `validate_json` | `validateJson` | `json::validate` |
| Run an operation on a definition | `call_json` | `callJson` | `json::call` |
| Run an operation on a built calendar | `cal.call_json` | `cal.callJson` | `cal.call_json` |
| The calendar's id | `cal.calendar_id` | `cal.calendarId` | `cal.calendar_id()` |
| The canonical form of the definition | `cal.canonical_json` | `cal.canonicalJson` | `cal.canonical_json()` |

The calendar's id, `calendar_id`, is the first 16 hex digits of the SHA-256 of the canonical form. The JavaScript package also exports `coreVersion()`, the version of the Rust core compiled into it.

## validate

Checks a definition and reports every error it finds, sorted by path and then by code. For a valid definition, Python and JavaScript return `ok`, the `calendar_id` and the canonical form; Rust's `from_json` returns the calendar, whose `calendar_id()` and `canonical_json()` give the same values. The Python and JavaScript `validate` functions return the errors instead of raising them. [Write a definition](/guides/write-a-definition/#no-defaults-for-your-organisations-choices) shows an invalid definition.

The example labels fiscal year 2023 under the default scheme, `by_start`, and under `by_end`, which number a year by the calendar year it starts and ends in.

## explain
